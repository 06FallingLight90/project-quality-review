# 质量属性指标审查清单

架构质量分两类：**内部质量**（架构文档、数据、图表、模型以及组件、连接件、配置、数据、接口的质量，开发期可评估）与**外部质量**（系统运维过程中体现出的与架构有关的质量属性，运行期才完全显现）。审查时对两类分别评估。

## 1. 内部质量指标

逐项检查架构是否支撑以下属性，每项判定必须落到具体代码/结构证据：

| 指标 | 审查要点 | 典型反例证据 |
|------|----------|--------------|
| 可维护性 | 改一个业务规则要动几处？模块是否可独立修改 | 一处逻辑散落 N 个文件；修改需理解全链路 |
| 可重用性 | 领域逻辑是否与框架/IO 解耦，能否被其他上下文复用 | 服务层直接耦合 ORM 模型与 HTTP 对象 |
| 可移植性 | 平台/环境相关代码是否隔离在适配层 | 业务代码中散落 OS 判断、硬编码路径 |
| 可集成性 | 对外接口是否稳定、契约是否明确 | 无 API 契约、内部结构直接暴露给外部 |
| 可测试性 | 模块能否独立实例化与验证 | 全局单例不可替换；依赖无法注入/打桩 |

## 2. 外部质量指标

通过代码结构与配置推断系统能否达成以下运行期属性，标注"推断"并给出验证方式：

| 指标 | 架构支撑点 | 审查线索 |
|------|-----------|----------|
| 性能 | 缓存层、异步处理、N+1 查询风险、阻塞调用 | 循环内远程调用；无分页的全表加载；同步串行链路过长 |
| 可用性 | 重试/降级/熔断、无单点、优雅停机 | 依赖链无任何容错；关键路径强依赖单实例 |
| 可靠性 | 事务边界、幂等设计、失败恢复 | 跨服务操作无补偿；消息无幂等消费 |
| 安全性 | 认证鉴权集中化、输入校验边界、密钥管理 | 密钥硬编码；鉴权逻辑散落各处易漏 |
| 易用性（运维） | 健康检查、结构化日志、配置外部化 | 无健康端点；日志无请求上下文；配置散落 |

## 3. 质量属性场景（评估外部质量的手段）

每个外部质量判断用六要素场景表述，避免空泛结论：

1. **刺激源**：谁/什么触发（用户、外部系统、运维、故障）
2. **刺激**：具体事件（并发达到 1 万、依赖服务超时）
3. **环境**：发生条件（正常运行、过载、升级中）
4. **制品**：作用对象（整个系统、某模块）
5. **响应**：系统应如何表现（降级返回缓存数据、2 分钟内扩容）
6. **响应度量**：可量化的达标标准（错误率 <0.1%、恢复时间 <30s）

审查输出格式：`[属性] 场景描述 → 当前架构能否达成 → 证据 → 差距`。

## 4. 质量效用树（优先级排序工具）

构建两维树：根为"质量效用"，第二层为质量属性（性能/可用性/可修改性…），叶子为具体场景。每个叶子标注两维优先级：
- **重要性**：H/M/L（对业务成功的影响）
- **难度**：H/M/L（当前架构实现的挑战）

输出 (重要性, 难度) 组合：(H,H) 是架构关键风险点，必须优先分析；审查报告中用效用树呈现 TOP 5-10 场景，替代泛泛的"质量概况"。

## 5. 权衡识别

- 多数质量属性互相制约：性能 vs 安全（加密开销）、灵活性 vs 易用性（配置复杂度）、一致性 vs 可用性。
- 审查时找出**当前设计显式或隐式做出的权衡**，并判断：是否有意识的选择（有文档/注释/结构痕迹）还是无意识的后果。
- 无意识的权衡是 P0 级风险信号——团队不知道自己牺牲了什么。
