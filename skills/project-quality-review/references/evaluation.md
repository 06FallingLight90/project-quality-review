# 架构评估方法清单

三类评估技术按评估者要求、客观性、适用时机选用；对 AI 辅助审查，场景法+度量法为主，检查表法为辅。

## 1. 评估技术三分类

| 技术 | 通用性 | 对评估者要求 | 客观性 | 适用时机 |
|------|--------|--------------|--------|----------|
| 问卷调查/检查表 | 通用或特定领域 | 简单了解 | 主观 | 早期、中期 |
| 基于场景 | 特定领域 | 比较熟悉 | 比较主观 | 中期 |
| 基于度量 | 通用或特定领域 | 精确掌握 | 比较客观 | 后期 |

本 skill 的对应策略：检查表（references 各清单）→ 场景（quality-attributes.md 第 3 节）→ 度量（scripts/dependency_metrics.py + metrics-evolution.md）。

## 2. ATAM 体系结构权衡分析方法（轻量适配版）

完整 ATAM 是多角色工作坊；AI 审查按其核心概念执行单线程分析：

**核心概念**：
- **敏感点**：某个质量属性的达成高度依赖的构件/参数（如"并发用户数超过阈值时消息队列长度成为性能瓶颈"）。
- **权衡点**：同时影响多个质量属性的决策（如"引入加密提升安全性但降低性能"）。
- **有风险决策 / 无风险决策**：可能引发问题的架构决策 / 已验证安全的决策。审查输出按此归类。
- **质量效用树**：见 quality-attributes.md 第 4 节。

**精简评估步骤**（原 9 步的 AI 适配）：
1. 表述评估目标与范围（用户指定的关注点）
2. 收集商业/业务动机（README、需求文档、领域推断）
3. 收集架构描述（入口点、模块图、配置）
4. 识别架构方法/风格（分层？事件驱动？微服务？）
5. 生成质量效用树（TOP 5-10 场景）
6. 逐场景分析架构方法：定位敏感点、权衡点、风险决策
7. 汇总风险清单，按效用树优先级排序

## 3. SAAM 场景分析法（轻量适配版）

适用：评估架构的**可修改性**（预测变更的影响）。

1. **场景开发**：从需求文档/Git 历史推断典型变更场景（新渠道、换存储、加报表）
2. **场景分类**：直接场景（无需改架构即可支持）/ 间接场景（需要修改架构）
3. **单场景评估**：对间接场景，列出需修改的构件、预估改动范围
4. **场景交互**：多个场景命中同一构件 → 该构件职责过多（潜在上帝模块）
5. **总体评估**：按改动集中度与成本排风险

Git 历史是免费的场景库：改动最频繁的文件组合暴露真实变更场景（`git log --name-only` 统计）。

## 4. 输出要求

- 每条评估结论标注方法来源（检查表项 / 场景编号 / 度量指标值）。
- 风险决策列表格式：`决策 → 影响的属性 → 场景证据 → 建议`。
- 无法确认的结论标注"推断 + 验证方法"。
